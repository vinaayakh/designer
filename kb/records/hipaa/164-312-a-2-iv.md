## Requirement

> **(iv) Encryption and decryption (Addressable).** Implement a mechanism to encrypt and decrypt electronic protected health information.
> — 45 CFR §164.312(a)(2)(iv), part of the Access control standard §164.312(a)(1)

"Addressable" is not optional. Under §164.306(d) the entity must implement it if it is reasonable and appropriate. Otherwise it must document why not and adopt an equivalent alternative. In practice, cloud data stores that hold ePHI are encrypted.

Rule status: the December 2024 proposed rule would make this specification *required*. As of 2026-10 it is not final (expected 2027). Re-check when it is.

## How to check on a diagram

- Every Node with Data Classification `PHI` is marked encrypted at rest, or is a Service that encrypts by default.
- That includes caches, queues, search indexes, backups and object stores, not only the primary database.
- A key-management Node (KMS / Key Vault) is present when customer-managed keys are claimed.

## Suggested fixes

- Turn on storage-level encryption for each PHI data store, and add a key-management service for customer-managed keys.
- If a store can't be encrypted, keep PHI out of it, or record the documented alternative in the Design Rationale.
